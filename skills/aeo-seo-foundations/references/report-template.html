1 · How search and AI search find you

Google

Crawlers read your pages, add the ones they trust to the index, then rank them for each search. Where you land depends on whether the page answers the search, and how much Google trusts the domain.

AI answer engines

ChatGPT, Claude and Perplexity run their own searches on engines like Google and Bing, read the top results, and cite a few pages. If search engines can't find you, the AI can't either.

What this audit checks

That your pages are quotable (A), found fast (B), never contradict each other (C), and that the setup keeps itself right on every new page (D).

2 · Critical findings

These break indexing or split your ranking credit. Fix them first.

Critical C1 · C2 · C3 Head and metadata

The site lives at two addresses, and the pages disagree about which is real

Evidence

ledgerly.dev redirects to www.ledgerly.dev with a 307, but every canonical and og:url points at ledgerly.dev. The sweep found 84 of 84 pages with a canonical on the wrong host, and og:url set to the homepage on all of them.

Where it lives

src/app/layout.tsx (hardcoded metadataBase), vercel.json (redirect)

The principle

To a search engine, ledgerly.dev and www.ledgerly.dev are two different sites. When the server says one and the pages say the other, every link takes a detour and ranking credit splits between them. Pick one host and make every page, link and file say it.

Prompt to fix it
Make https://www.ledgerly.dev the only host. In src/app/layout.tsx, set metadataBase to it and give every page a self-referencing canonical and an og:url equal to that canonical, with no query string. In vercel.json, change the bare-domain redirect to a permanent 308 in one hop. Then run the build and curl three pages to confirm the canonical, og:url and redirect.
Effort: SOwner: agent
